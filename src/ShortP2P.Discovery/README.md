# ShortP2P.Discovery

Обнаружение пиров в локальной сети по **UDP**: маяки, идентификация, события о найденных узлах. Опирается на типы из
`ShortP2P.Transport` (UDP).

## Граница слоя (Discovery / Retranslation)

Подсистемы **Discovery** и **Retranslation** относятся к сетевому **overlay-слою** (поиск узлов, маршруты, ретрансляция)
и реализуются **вне прикладного** `ShortP2P.Client`: в **отдельном проекте или наборе проектов** решения, которые
ссылаются на транспорт и при необходимости на общие типы, но не тянут за собой UI, SQLite и пользовательские сценарии.

Сейчас в этом слое находится **`ShortP2P.Discovery`** (UDP-маяки и сервис обнаружения). Логика **ретрансляции** и
дальнейшее обогащение discovery (в т.ч. перенос presence/ping и LAN-сканирования из `ShortP2P.Client`) оформляются в той
же архитектурной зоне: либо расширением существующей сборки, либо **отдельным проектом** в решении (например, выделенная
сборка под relay), с зависимостью `ShortP2P.Client` → overlay-проекты, а не наоборот.

## Узел и возможности (capabilities)

**Узел (нода)** — устройство с установленным приложением ShortP2P, выступающее как участник overlay: у него есть сетевой
адрес, идентичность в сети и набор **ролей**, которые он готов выполнять.

В **presence / discovery ping** (см. `PresencePingCodec`, `PresencePeerCapabilities` — пока в `ShortP2P.Client`, перенос
в overlay-слой по мере рефакторинга) узел передаёт 16-битную маску заявленных возможностей. Это единый перечень того,
«что умеет» нода с точки зрения протокола; остальные подсистемы (мессенджер, ретранслятор, хост приложений) при старте
или в настройках должны согласовываться с этой маской.

### Полный список продуктовых ролей

| Роль                   | Смысл                                                                                                                                                          | В wire (`PresencePeerCapabilities`) | По умолчанию в пинге                                                                                                                               |
|------------------------|----------------------------------------------------------------------------------------------------------------------------------------------------------------|-------------------------------------|----------------------------------------------------------------------------------------------------------------------------------------------------|
| **Messaging**          | Прямой приём и передача сообщений чата (основной P2P-канал приложения).                                                                                        | `Chat`, бит 0                       | Да — клиент **всегда** выставляет этот бит при сборке пинга и при разборе считает Messaging включённым, даже если поле маски отсутствует (legacy). |
| **Discovery**          | Поиск и объявление узлов: участие в discovery-слое (LAN, при необходимости другие транспорты), ответ на запросы обнаружения, поддержание списка видимых пиров. | `PeerSearch`, бит 1                 | По мере реализации; пока флаг зарезервирован.                                                                                                      |
| **Retranslation**      | Ретрансляция данных для других узлов (мост/relay), когда прямой путь недоступен.                                                                               | `Relay`, бит 2                      | По мере реализации; пока флаг зарезервирован.                                                                                                      |
| **ApplicationHosting** | Хостинг вынесенной логики: приложения, боты, сценарии на стороне узла (не часть базового чата).                                                                | `BotHosting`, бит 4                 | На будущее; имя члена enum историческое (`BotHosting`).                                                                                            |

### Зарезервировано в маске пинга (вне четырёх ролей выше)

| Бит | Идентификатор в коде        | Назначение                                                                                                             |
|-----|-----------------------------|------------------------------------------------------------------------------------------------------------------------|
| 3   | `EncryptedTemporaryStorage` | Зарезервировано под зашифрованное временное хранилище на узле; не входит в текущий продуктовый набор из четырёх ролей. |

При расширении протокола новые биты добавляются только с обновлением `AllDefined` и документации; при приёме неизвестные
биты маскируются и игнорируются.

## Структура

| Файл                                                     | Назначение                                     |
|----------------------------------------------------------|------------------------------------------------|
| `IPeerDiscoveryService.cs`, `UdpPeerDiscoveryService.cs` | Контракт и реализация сервиса discovery        |
| `UdpPeerDiscoveryOptions.cs`                             | Параметры (порты, таймауты и т.д.)             |
| `DiscoveredPeer.cs`, `PeerIdentity.cs`                   | Модели найденного пира и идентичности          |
| `DiscoveryBeaconCodec.cs`, `CompressedNetworkId.cs`      | Кодирование маяков и сжатый идентификатор сети |
| `DiscoveryNotifications.cs`                              | Уведомления о событиях discovery               |

Зависимость: `ShortP2P.Transport`.
